# ADR-001 — Local-First Inference via Explicit LangGraph Routing (no cloud LLM dependency)

- **Status:** Accepted
- **Date:** 2026-09-12
- **Deciders:** Solo maintainer (portfolio architecture)
- **Related:** `core/graph.py`, `agents/base.py`, `core/ollama_client.py`, `core/config.py`, `agents/registry.py`

## Context

The system's value proposition — agency/freelance pipelines for outreach, SEO, content, and code — collapses if every task pays per-token cloud margin. Three forces shaped the decision:

1. **Cost & privacy.** Client data (leads, sites, inboxes) cannot leave the machine; recurring cloud inference at pipeline volume is a five-figure annual cost.
2. **Deterministic control flow.** Ad-hoc "let the LLM decide everything" agent loops are unauditable and unbillable. The business needs a routing trace it can show a client.
3. **Hardware reality.** Target user has a single workstation, not a GPU cluster — so models must be quantized GGUF served by Ollama, with an optional OpenAI-compatible escape hatch (NVIDIA NIM) rather than a hard cloud requirement.

Alternative considered: cloud-first agents (OpenAI/Anthropic) with a local cache. Rejected — recurring marginal cost, data egress, and it makes the "you own the pipeline" sales story false.

## Decision

1. **All inference routes through local Ollama.** Model selection is a static, class-level property per agent (`model = settings.model_fast` / `model_reason` / `model_vision`, quantized GGUF). `NimClient` is an optional OpenAI-compatible accelerator behind the same interface — never a requirement.
2. **Explicit state-machine routing over autonomous loops.** Agents never call each other ad hoc. Every agent returns a typed partial `AgentState`; the **Orchestrator** sets `next_agent`; the compiled LangGraph routes `START → orchestrator → specialist → orchestrator → …` and terminates when `state["result"]` is set. Hard guards: orchestrator bails after 5 retries, LangGraph `recursion_limit=50`.
3. **Structured outputs only.** Every agent returns a `dict` (12-factor #4); the orchestrator's routing decision is a JSON object `{"next_agent", "reasoning", "subtask"}` parsed from the LLM — natural language in, typed control flow out.
4. **Unified state.** One `AgentState` TypedDict carries both conversation (`messages`) and business fields (`task`, `context`, `result`, `error`, `retries`, `agent_path`) — execution state and business state are the same object (12-factor #5).
5. **Observability by construction.** `AgentGraph.register()` wraps every agent in a `_tracked` shim that appends to `agent_path`; `BaseAgent.__call__` adds tenacity retry (exponential backoff), per-agent Redis metrics, and a consistent `error_result` that always routes back to the orchestrator.

## Consequences

**Positive**
- **$0 marginal inference cost** — the pitch "your pipelines are an asset, not a subscription" is literally true.
- **Auditable routing** — `agent_path` gives a per-run trace a client can be shown; this is a sales artifact, not just debugging.
- **Fail-closed and local** — no data egress; auth middleware refuses to serve when `API_SECRET` is unset.

**Negative / accepted trade-offs**
- **Quality ceiling** — small quantized local models under-perform frontier cloud models on open-ended reasoning; mitigated by routing hard reasoning to `MODEL_REASON` and by the orchestrator retry loop, not eliminated.
- **Singleton graph** — `get_graph()` is a module-level singleton and `register_all_agents()` is not idempotent (double registration accumulates nodes); acceptable because the process model is one API server per machine, and tests use session-scoped fixtures.
- **Static model binding** — model is chosen at import time, not per-request; changing models means redeploying, not a config toggle at runtime.

**Follow-ups**
- 12-factor #7 (contact-humans-as-tools) is deliberately unimplemented — noted in `AGENTS.md`.
- Optional NIM path exists for users who *want* cloud speed; keep it behind the same `OllamaClient` interface so the local-first guarantee is never violated.
